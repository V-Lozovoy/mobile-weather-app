# Weather - SP2

Стрічка трьохсот міст і навігація: таби, стек, параметр. React Native +
**Expo SDK 57**, TypeScript, expo-router.
**Цей файл і є завдання** - специфікація, критерії та бали нижче.

Заготовка **працює одразу**: запускається, показує стрічку трьохсот міст і
два таби. Неправильна в ній дві речі: стрічка знизу - `ScrollView`, що
монтує всі триста рядків заздалегідь, а тап по картці нічого не відкриває.
П'ять TODO - і всі п'ять про одне: показувати список правильно і ходити
між екранами.

## Як працювати

Кожен TODO живе в одному файлі, і під кожним лежить **закоментований
каркас зі слайда** - розкоментуйте, адаптуйте і доповніть своїм. Каркас
дає механіку; **верстка картки стрічки й екрана міста - ваша власна
робота**, ніхто її за вас не намалює.
Після кожного кроку застосунок лишається робочим - одразу видно у Expo Go,
що саме змінилося.

## Завдання

Зібрати навігацію: корінь-`Stack`, два таби, екран міста за параметром.

| # | Що зробити | Де |
|---|---|---|
| 1 | Лінивий список замість `ScrollView`+`map`: чотири пропси + власна верстка картки (місто, країна, температура) | `app/(tabs)/index.tsx` |
| 2 | Оголосити екран міста в кореневому `Stack`, дати заголовок | `app/_layout.tsx` |
| 3 | Іконки обом табам: `tabBarIcon` з Ionicons | `app/(tabs)/_layout.tsx` |
| 4 | `id` з адреси рядком, власна верстка екрана міста, стан «не знайдено» | `app/city/[id].tsx` |
| 5 | Тап по картці → `router.push(cityPath(id))` | `app/(tabs)/index.tsx` |

Автоперевірок у цій роботі нема - кожен крок видно на екрані телефона.
Розкоментований приклад - це ще не зроблений крок: працює той код, що живе
поза коментарями.

## Оцінювання

**SP2 - 15 балів.**

| Що |
|---|
| Лінивий список: `FlatList` із чотирма пропсами, розділювач - окремий компонент; картка показує місто, країну й температуру - верстка власна |
| Кореневий `Stack` оголошує `city/[id]`; у обох екранів заголовки |
| Два таби перемикаються, скрол не губиться, у кожного - іконка Ionicons |
| `id` читається з адреси рядком; екран міста - повна верстка (не один рядок); невідомий `id` має свій стан «не знайдено» |
| Тап по картці відкриває `/city/<id>` через `push` - «назад» повертає на стрічку |

Обов'язкова умова: застосунок запускається в Expo Go без червоного екрана,
а всі п'ять пунктів видно на відео.

Знімається: `replace` замість `push` («назад» не працює); об'єкт міста,
покладений у параметри маршруту замість `id`; `keyExtractor` по індексу;
прибраний готовий `headerShown: false` у табах - header задвоїться;
картка чи екран міста, що лишились одним рядком тексту зі стартової
заготовки, - верстка і є частина роботи.

## «Зроблено» виглядає так

Два таби з іконками, стрічка скролиться без спалахів, картка показує місто,
країну і температуру, тап по картці - екран міста без таб-бару, назад - на
ту саму позицію скролу. Невідомий `id` (наприклад, `weathercities://city/nope`)
- спокійний «Місто не знайдено», а не крах.

## Чого тут немає

Мережі - SP3. Пошуку - SP4. Мапи - практики на неї в короткому курсі немає
взагалі, тому й таба Map тут нема. Уся арифметика стрічки (`keyOf`, `rowOf`,
`findCity`, `cityPath`) - готова в `src/lib`, її писати не треба.
Схема `weathercities://` в `app.json` уже стоїть - вона потрібна слайду про
deep links (S2 · 16) і перевірці на пристрої, самим її прописувати не треба. Сьогодні навігація - таби, стек і параметр.
