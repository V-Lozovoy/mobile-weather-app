# Weather - SP3

Список міст і погода на наступному екрані: живий WeatherAPI, TanStack Query,
кеш на 5 хвилин. Ключ API вже вшитий у заготовку - реєструватися не треба.
React Native + **Expo SDK 57**, TypeScript, expo-router.
**Цей файл і є завдання** - специфікація, критерії та бали нижче.

Заготовка запускається: список міст зелений, тап веде на екран погоди -
а там заглушка: місто знаходиться, погоди нема. Написати запит, навчити екран
трьом станам і розкласти відповідь на екран - ваша робота. Мапера в цій парі
нема свідомо: WeatherAPI віддає дані вже готовими - у °C, словами і з
іконкою, тому відповідь достатньо типізувати.

## Завдання

Навчити екран погоди ходити в мережу: URL із ключем, запит, useQuery - і
дані з відповіді просто на екран.

| # | Що зробити | Де |
|---|---|---|
| 1 | URL прогнозу: `key`, `q`, `days=3` через `URLSearchParams` | `src/lib/urls.ts` |
| 2 | Запит: `fetch` + перевірка `response.ok` + текст помилки з тіла відповіді | `src/lib/api.ts` |
| 3 | Екран погоди на `useQuery`: ключ `['weather', name]`, `staleTime` 5 хв, стани: завантаження / дані / помилка з Retry | `app/city/[id].tsx` |
| 4 | Дані на екрані: current і сьогоднішні години з `forecastday[0]`; pull-to-refresh | `app/city/[id].tsx` |

Ключ - у `src/lib/urls.ts` (`WEATHERAPI_KEY`), він уже працює. Документація
ендпоінта: WeatherAPI → Forecast → `forecast.json`. Готовий URL із TODO(1)
можна відкрити в браузері й бачити ту саму відповідь, яку типує
`WeatherResponse` у `src/types.ts`.

## Оцінювання

**SP3 - 25 балів.**

| Що |
|---|
| `buildWeatherUrl` збирає правильний URL (звіряється браузером) | 
| Запит: `response.ok` перевірено; помилка несе текст із відповіді API («No matching location found»), а не «HTTP 400» |
| Екран погоди на `useQuery` з ключем `['weather', name]` і `staleTime`; три стани; Retry справді перезапитує | 
| Дані на екрані: температура, умова, іконка, мета-рядок, години сьогодні; pull-to-refresh |

Обов'язкова умова: на телефоні живі дані WeatherAPI (ключ уже в репозиторії),
скріншоти у Classroom: список міст, екран погоди з годинами, екран помилки
з Retry (режим літака) - і коротке відео: вийшли з міста й повернулися -
дані миттєво без запиту, потягнули вниз - оновилося.

Про «порожньо» чесно: на екрані одного міста порожнього стану не буває -
або погода є, або помилка. Його час прийде в SP4, коли пошук часом не
знаходить нічого.

Знімається: `fetch` без перевірки `response.ok` - на неіснуючому місті
екран покаже сміття замість «No matching location found»; ключ у
компоненті замість мережевого шару; `staleTime` 0 (або без нього) - кожне
повернення на екран рефітчить; Retry, який нічого не викликає; години з
`forecastday[1]` - це завтра.

## Здати

Код у вашому репозиторії **до дедлайну**, три скріншоти (список, дані з
годинами, помилка з Retry) і відео кешу на 10 секунд у Classroom.

Три питання про ваш код:

1. WeatherAPI відповів 400 із `{ error: { message } }` - чому `fetch` не кинув
   виняток сам, і звідки на екрані текст причини?
2. Ви вийшли з екрана міста й одразу повернулися - скільки запитів полетіло
   і чому саме стільки? А якщо повернутися через десять хвилин?
3. Чому ключ живе в `src/lib/urls.ts`, а не в компоненті екрана?
